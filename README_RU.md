## ✨ Основные возможности HuiJuiSU NEXT

### Автономный центр инструментов

Нижняя навигация была переработана в **5 вкладок**: Главная / **Инструменты** / Суперпользователь / Модули / Настройки.

Инструменты отделены от главной страницы, чтобы избежать высокой плотности информации и сделать их более доступными.

### 7 мощных инструментов

| Функция | Описание |
|---|---|
| **Проверка здоровья в один клик** | Батарея / Температура / Загрузчик / Ядро / Root / SELinux / Хранилище |
| **Режимы производительности** | Энергосбережение / Баланс / Производительность / Игры, четыре профиля планирования системы |
| **Пакет резервного копирования в один клик** | boot + init_boot + vbmeta + снимки модулей, с включенным restore.bat |
| **Восстановление после кирпича в один клик** | Одноclick-ное восстановление dd из каталога резервных копий, опциональное восстановление состояния модулей |
| **Загрузка ядра GKI** | Перенаправления на предварительно скомпилированные ядра сообщества специально для режима built-in |
| **Прошивка кастомного ядра** | Поддерживает форматы `.img` (built-in) и `.ko` (LKM) |
| **Менеджер приложений** | Заморозка / Разморозка / Принудительная остановка / Очистка данных / Удаление (текущий пользователь) |

### Встроенное скрытие (самое сильное по умолчанию)

HuiJuiSU NEXT использует стратегию скрытия **ready-out-of-the-box**:

- **Скрытие путей**: 8 критических `sus_path` (ksu / ksud / modules / magisk / tmp и т.д.)
- **Скрытие монтирования**: `hide_sus_mnts_for_non_su_procs` скрывает точки монтирования sus
- **Подмена логов**: `avc_log_spoofing` скрывает логи отказов SELinux
- **Скрытие статистики ядра**: `sus_kstat` переопределяет `/system` и `/vendor`
- **Автоприменение**: Тихо выполняется в фоновом режиме при запуске приложения и автоматически переapplied после обновления правил

### Снимки модулей

Резервное копирование автоматически записывает статус включения/удаления всех модулей в `/data/adb/modules/` в `modules.json`.

При восстановлении после кирпича установка флажка "Также восстановить состояние модулей" автоматически восстанавливает модули до конфигурации на момент резервного копирования, **устраняя необходимость вручную включать их по одному**.

### Прошивка кастомного ядра

Решение проблем режима built-in на устройствах GKI:

- **Формат `.img`**: Прошивка dd с правами Root + обработка проверки vbmeta (защита от отката) + опциональная очистка остатков LKM
- **Формат `.ko`**: Вызывает `ksud boot-patch -f -m` для автоматической инъекции
- **Умное распознавание**: Автоматически определяет тип и размер файла, чтобы предотвратить прошивку неправильного файла

## 🧩 Основные функции, унаследованные от BakaSU

1. Управление `su` и правами Root на основе ядра
2. Модульная система на основе [metamodules](https://kernelsu.org/guide/metamodule.html)
3. [App Profile](https://kernelsu.org/guide/app-profile.html): Заприте права Root в клетке
4. Поддержка non-GKI и GKI 1.0
5. Поддержка нескольких менеджеров (официальный KernelSU / KOWSU / BakaSU)

## ⚙️ Состояние совместимости

- Официально поддерживает устройства Android **GKI 2.0** (ядро 5.10+)
- Старые ядра (3.4+) также совместимы, но требуют самостоятельной компиляции ядра
- Поддерживаемые архитектуры: `arm64-v8a`, `armeabi-v7a`, `x86_64`
- Встроенный [SUSFS](https://gitlab.com/simonpunk/susfs4ksu) **поддерживает только** бэкпорты на ядро 4.3+
- `Tracepoint Syscall Redirect hook` поддерживает только ядра GKI2 (5.10+)

---

## 🪝 Режимы хуков

- **`Tracepoint Syscall Redirect hook`**: Режим хука по умолчанию, от upstream, поддерживает только ядра GKI2 с ABI `arm64-v8a` или `x86_64`
- **`Manual Hook`**: Наиболее совместимый хук, поддерживает ядра Linux от 3.4 до 6.18
- **`SUSFS Inline Hook`**: Хук от [SuSFS](https://github.com/simonpunk/susfs4ksu), аналогичен `Manual Hook`

## 🔧 Оптимизация производительности

### Логи горячих путей ядра

v3.0.0 преобразовала все вызовы `pr_info` в высокочастотных путях вызовов ядра в `pr_debug`, включая:

- `syscall_hook.c` (arm64/x86_64/riscv64): 37 экземпляров
- `ksud_integration.c`: 18 экземпляров
- `setuid_hook.c`, `sucompat.c`, `dispatch.c`, `supercall.c` и т.д.: 80+ экземпляров

### Быстрый возврат sulog

Добавлен быстрый возврат в `ksu_sulog_emit_grant_root`, экономящий последующую логику для каждого `setresuid` при отключенном sulog.

## ⚠️ Уведомление об обновлении

### Изменение имени пакета

- **Старые имена пакетов**: `com.huijui.manager` / `com.huijuisu.huijuisu`
- **Новое имя пакета**: `com.huijui.sunext`

Для обновления со старой версии необходимо сначала удалить старую версию, а затем установить новую.

### Состояние после обновления

| Элемент | Статус |

| Состояние включения модулей | ✅ Сохранено |
